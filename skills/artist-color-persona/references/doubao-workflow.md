# 豆包及其他 Agent 宿主的执行说明

本页说明如何完整执行 Skill，不承诺某个客户端版本必然有 Image、Python 或文件交付能力，也不假定固定菜单位置、工具名或 API 参数。

## 安装与首次使用

1. 取得发布的豆包安装 ZIP。该包首层直接有 `SKILL.md`、`scripts/`、`references/`、`assets/`；目录安装包则以 `artist-color-persona/` 包住相同内容。按当前宿主要求选择，不要只上传一份说明文档。
2. 在实际客户端的 Skill 导入／安装入口导入并启用。没有该入口则说明当前环境不支持安装；把 ZIP 发进普通聊天不能自动证明安装成功。
3. 附原片，可说“从这十位艺术家选一位适合它的，为我调色”，或“同一张图交给莫奈与梵高，各做一版”。用户不必预先选画或写美学术语。
4. 阅读入口，找到当前附件与实际工具；不照抄示例路径、另一台电脑路径或工具参数。

## 先确认能执行到哪一步

根据真实工具说明、可访问文件及工具返回确认能力，不只依据角色自述“我能做”。

| 能力 | 需确认事实 | 缺少时处理 |
| --- | --- | --- |
| 看附件和真画 | 实际读到两图像素，知道各自文件或附件标识。 | 取得可查看文件；不据文件名选画。 |
| 同次双图编辑 | 同一次编辑确实接收原片与真实画作，能区分图 1、图 2。 | 停在准备阶段，不用单图加风格文字冒充。 |
| 保存真实返回 | Image 已成功生成，结果能保存为可读文件。 | 说明只有可见样稿，取得实际文件后拟合。 |
| Python 与文件操作 | 能运行脚本和依赖，保存并交付 `.cube` 与最终照片。 | 交付已有图片和命令，明确 LUT 尚未完成。 |

能显示生成图，不必然能把实际图像文件交给 Python。这两点分别确认。不要编造路径、沙箱地址、下载链接或成功回执。

## 给执行能力较弱的 Agent 的短流程

每完成一步再进入下一步，不需要向用户展示冗长内部推理。

### A. 找原片、选角色

查看照片，记录主体、光线与一至两组色彩关系；用户点名则沿用，否则按 [routing.md](routing.md)在十位中选一位。给一句选择理由，先不写艺术家对白，不要求用户代做每个细节判断。

### B. 找真实参考画

从索引进入该艺术家的 manifest，选择有出处的作品。未随包附图则按 [作品获取](artwork-image-lut.md#取得真实作品文件)取得私有缓存或导入用户的单幅真画。实际查看，记录标题、年份、来源和文件，不能以肖像、合影、多图网页截图或前次生成图充数。

### C. 准备双图输入

从实际 Skill 目录运行 `scripts/artwork_image_lut.py prepare`，完整示例见 [准备任务](artwork-image-lut.md#准备任务)。读取实际 `job.json`，确认两条 `image_inputs` 正确。用当前宿主的双图编辑工具同次提交图 1 原片、图 2 真画，发送 `prompt.txt` 原文，不加对白或长限制。配色与强度以参考画为主。

### D. 保存返回、导出 LUT

保存本次实际返回，对原 `job.json` 执行 `finish`。读取 `result.json`，打开其中 LUT、原尺寸照片、Image 归档，核对文件存在和尺寸。Image 重绘与 LUT 拟合分别展示；强烈颜色本身不作为缺陷或减弱依据。

### E. 最后由艺术家解释

LUT 照片确已生成并查看后，才让角色用第一人称解释本次配色、参考作品与相关理念。用“莫奈：我……”等姓名标签，整体说明一次角色模拟，不反复在名字前加“AI”。依据实际成片，不编造局部手工调整；只追问已有成片时读取旧任务回答，不需重新生成。

## 每步留可恢复记录

至少保存：原片、角色 ID、作品标题／年份／来源、两张实际上传图、原文提示词、实际 Image 返回、LUT、最终照片和任务 JSON。可用以下状态概括，只有对应文件实际存在才推进：

| 状态 | 已完成的东西 |
| --- | --- |
| 已选画 | 原片和真画已看，选择依据与来源已记录。 |
| 已准备 | `job.json`、两张上传图、`prompt.txt` 已存在。 |
| 已生成 | 实际 Image 返回已保存且可读取。 |
| 已拟合 | `.cube`、原尺寸照片已保存且重读核对，`result.json` 存在。 |
| 已解释 | 已查看成片，人物说明与本次输出关联。 |

仅完成前半段时直接说，例如“已保存 Image 迁色样稿，当前环境不能运行 Python，LUT 尚未导出”。保留已有内容和缺失步骤，不拼凑不存在的完整演示。

## 展示顺序

每位各自整理：**00 相机原片 → 01 真实参考画作 → 02 Image 生成效果 → 03 原尺寸 LUT 成片 → 04 对应 `.cube`**。后面附人物说明、实际提示词与来源。对比用同一原片，分别保存各位输出，提供真正可打开的文件或附件。

本说明是通用宿主执行规范，不表示所有豆包客户端、模型等级或 Skill 入口都已实机测试；可用能力与操作以用户当前环境为准。
