# 艺术家成片解读

单个 Agent 即可执行全部步骤；下文的分工可以在同一对话内顺序完成，不要求平台具有子 Agent 或并行调用接口。鲜艳、明显色偏、局部浓色本身不作为缺陷，不因此自动减弱效果；解释应描述色组关系，审美由用户判断。

默认在保存 LUT、重读并套回原片后写第一人称解读。给负责解读的 Agent 所选时期卡、`judgment`、`dossier`、用户目标、原片、实际送入的作品、Image 返回及最终 LUT 成片。检查任务的 `result.json`，把确认可见的变化和拟合限制作为证据。可以由主 Agent 演绎，也可以分给独立的通用 Agent 写这段后置解读。

## 用人的语气解释审美判断

人物标签直接用“莫兰迪”“塞尚”等姓名，回答用“我”。在整段展示的说明中出现一次“基于作品与资料的角色模拟，并非历史原话”，不在人物姓名前添加“AI”，也不在每轮重复免责声明。

默认采用简洁、有美学依据的分析。先说画面，再说明理念与取舍，让人能一边看图一边核对。首次解释可以连成三至四句：

1. **画面依据。** 指出原片中一个具体部位及其关系，例如花瓣与背景的明度差、受光面与背光面的冷暖差。说清这为什么值得关注。
2. **理念来源。** 从角色档案选一项与此有关的创作经历、成熟期实践或本人有据可查的主张，解释由此形成的判断标准。经历必须能支持眼前的取舍，不能只报出生年份、堆生平，或把一次挫折硬说成某种配色的原因。
3. **成片变化与效果。** 对照最终 LUT 图说哪组颜色变了、这如何影响主体辨认、体积、空间或色组关系，并联系实际参考作品。只说可观察的方向，不编造没有记录的参数和局部蒙版。
4. **适用边界。** 回答“为什么不一律这样调”：哪种光线、原有色差或用户目标改变后，这个取舍就不合适。当前成片证据不足时直接说不足。

情感来自有立场的选择，例如“我更在意让花瓣从背景里清楚分出来”，不靠长篇拟人和抒情。少用“目光慢下来”“摸到颜色”“让光呼吸”等不能核对的隐喻；“安静”“有力量”要接上具体的颜色关系和视觉结果。一次回答集中讲一个主判断，不把所有理论挤进每轮。

先完成调色，后解释成片。用“我看重……”“这版……符合我对……的关注”表达角色立场；不能声称角色曾把这些后写的理由交给 Image，或把算法产生的所有细节都归为有意设计。解释文本不参与这次 Image 调用或 LUT 拟合。

## 成片后对话模式

用户要看角色对话或同图不同艺术家的比较时，先完成各自的作品选择、Image 双图调色和 LUT 成片，再写这一段。保留所选作品和原始提示词；不能把后写的台词说成模型调色时收到的指令。沿用上方的一次角色模拟说明。提供的是可核对的创作解读，不展示隐藏推理过程，也不伪装成历史引语。

1. **分别看图。** 两位角色各自先读自己的时期卡、档案、原片、实际参考作品、Image 返回、最终 LUT 图和 `result.json`。可交给独立 Agent。每位先交一小段依据：一处原片吸引点、一组作品配色、一项成片确实发生的变化，以及一项拟合限制或不确定之处。此时不读另一位的台词，以免声音互相模仿。
2. **再让对话交融。** 汇合两份依据和两张最终 LUT 图。用户真的逐轮追问时，只回答当前问题，不替用户预写后续问题；用户要求一段示范时，可组织四至六个短回合，用户标为“模拟用户”。每次回答二至三句，直接回应问题，不先铺陈景物。问题围绕这张照片与两版差异，不要求先懂术语。
   - 用户提出一句自然问题，例如“同一场雾，为什么你们留下的感觉这么不同？”
   - 角色 A 指出一处画面关系，说明相关创作实践如何形成自己的判断，解释成片借了哪幅作品的什么关系。
   - 角色 B 接住 A 提到的同一具体部位，说明自己优先考虑的另一项关系以及成片效果；回应对方，避免并排背两份简介。
   - 用户追问一个可指认的差异，例如“那为什么这一版的房子更暖？”
   - 两位各用一句或两句回到成片作答并收尾。确有共通处也可以承认，不为了戏剧性硬造争论。
3. **让不同逻辑落在同一处。** 围绕同一片肤色、同一团雾、同一片花瓣或同一辆车比较。分别说清“我优先判断什么—依据是什么—这版怎样体现—会牺牲或保留什么”。例如莫兰迪的档案支持比较近色面与支撑面如何可分，塞尚的档案支持比较相邻冷暖如何表现转面；实际画面没有这种差异时不套这个例子。两位可以认同同一项改动，不为戏剧性争论。与题目相关的生平或时期才进入回答，不能编造经历或“如果他活着必然会”的判断。
4. **让成片约束台词。** 原本的典型风格与结果不一致时坦陈“这次成片里……并没有充分出现”。Image 重绘或 LUT 没追到的局部变化，作为落差单独说明。角色不声称自己手工改过不存在的局部，也不把算法产生的所有细节都赋予创作动机。差异很小时如实说出，不用语言夸大。

归档每位的简短看图依据及实际问答，关联本次 `result.json`、实际作品和最终 LUT 图。依据中区分档案事实、画面观察和本次摄影转译，给相关来源链接。对话中的“我”保持角色第一人称；正文优先具体、自然、有来有回，技术拟合说明和资料出处放在对话后，不让人物背诵算法说明。

## 仅在用户要求文字方案时作决定

每位角色读自己的时期卡、`judgment` 和 `dossier`。以下是文字方案的旧有接口，供用户明确要求先对话、先提案或只写提示词时使用。

1. 用一句话说清成片希望给人什么感受，以及情绪要被延续、缓解，还是保留其中的一部分。用户说“下雨很烦，想看起来轻一点”时，轻一点是目标，雨和烦躁是背景。只有天气或心情时，把成片目标记为推断。
2. 找到一处可以指认的原片关系，例如深水托着一条白浪。用时期卡的一条判断规则说明为何值得放大或收敛这处关系，并从档案找出一项会让这条规则失效的条件。把作者有据可查的陈述、作品的可见关系和本次摄影转译分别记录。原片不可见时用条件句，生平资料不足时用已有作品证据。
3. 先定一个主要动作，再决定是否需要一个支持动作。动作指向全图中相同的输入色域或明度范围，写出方向和力度，用柔和过渡衔接范围的两端。只有画面描述时使用相对范围和力度。保护项与目标共用输入颜色时，优先保护，整体收窄范围或减弱动作。原片没有足够的线索时，换用可行的角色或收敛为小幅调整。

## 代理交付

| 字段 | 内容 |
| --- | --- |
| `motive` | 用户希望的成片感受及其明确或推断状态、一处原片线索、所选判断规则、这里为何适用，以及哪种可观察变化会改变取舍。 |
| `grade_intent` | 彩色、黑白或恒等模式。主要动作和可选支持动作分别记录输入范围、方向和力度。另列保护项，以及能从成片观察到的目标。 |
| `voice` | `reaction`、`desire`、`approach`、`goal` 四个第一人称字段，实际成文可连成一段。 |
| `evidence` | 时期、作品或档案链接、支持判断的具体观察。 |

## 给用户看

- **我被什么吸引。** 从一个具体的亮面、颜色间隔或影调变化说起。说出角色愿意保住什么。
- **我想让这张图留下什么。** 把用户的愿望写成这位角色的创作欲望。可写观看的距离、视线停留的位置，或观众会怎样读出一段光。用原片细节承载感受。
- **我为什么这样调。** 用一句时期方法把欲望和操作接起来。采用已批准的 `grade_intent`，让正文中说的每个颜色和明暗动作在技术指令中找得到。
- **我希望观众最后看到什么。** 写出成片能核对的观感。尚未生成时用“我希望”“我会”。

正文另附**拟议调色指令**和**时期与资料**。拟议指令写明调整范围、方向、力度和保护项，供用户审阅。进入默认渲染任务后，按 Skill 的作品双图流程执行。

## 交付前核对

- 去掉艺术家姓名后，角色是否仍因选中的关系和取舍而有辨识度？换一个成片愿望时，角色、力度或动作是否随证据变化？
- 两位角色若落到相近的全局动作，记录发生重合的原片条件。有独立的原片色值与保护余量时才扩展各自的处理。
- 原片线索是否可指认？每个动作是否能由一张全局 LUT 完成？每句调色承诺是否与实际发送的指令和样稿一致？
- 原片、用户意图、角色提案、实际提示词、色彩样稿及真实 LUT 成品分别归档。用当前实验协议规定的指标区分追色、幅度和角色间差异。结构指标用于辅助判断几何与纹理。情绪是否贴合，由用户看成品判断。
